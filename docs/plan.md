# MeetKeep 开源版：范围与阶段

2026-11-21 对齐的结论。调研和实测的细节在 `docs/research/`，这里只写定下来的东西。

## 定位

开源的桌面会议记录应用，macOS 和 Windows 双端，个人使用。云端转写为主，数据存本地。不分第一版、第二版，按下面的阶段一次做完。

## 已定的决定

| 事项 | 决定 |
|---|---|
| 框架 | MyGo：界面用 TypeScript + React（系统 webview），业务用 Go |
| 原生层 | macOS 用 Swift，Windows 用 Rust；跨平台的计算（说话人识别、解码）用 Rust |
| 转写 | 默认 MAI-Transcribe-2 批量接口，本地切句后逐句送，不用流式。也能接 DeepSeek 的语音识别和自定义的 OpenAI 兼容服务（云端或自建），都不要求时间戳：会后在本地按停顿和换人切段，时间取切点 |
| 纪要与白板的模型 | Claude（Anthropic 的 Messages API）、DeepSeek、OpenRouter 或自定义的 OpenAI 兼容服务，设置页里切换，各存各的密钥和模型名，默认 DeepSeek |
| 配置 | 存 `~/.config/meetkeep/settings.json`，密钥明文写在里面，不用钥匙串；文件权限 0600 |
| 会中说话人 | 双轨区分：麦克风是「我」，电脑里的声音是「对方」 |
| 会后说话人 | 本地识别（`modules/speech`，Rust），不用云端的。线下会议同样适用 |
| 录音格式 | 采集 48kHz 单声道，每条轨存一个 Ogg Opus 文件（32kbps，两条轨一小时约 29MB），纯 Rust 编码（ropus），边录边落盘；切句和转写在内存里降到 16kHz |
| 跨会议认人 | 做。本地声纹库，用户主动点「记住声音」才入库 |
| 实时纪要 | 按话题追加的大纲，约 45 秒更新一次，只改最后两个话题，更早的冻结；每条可点回原句。会后另出定稿 |
| 实时白板 | Excalidraw 自由画板。模型只输出带稳定 ID 的节点和连线，坐标由程序排；用户动过的元素不再改。不走 Mermaid |
| 录制来源 | 默认麦克风加全部系统声音；可改为勾选一个或多个 App；开始前选定 |
| 开始方式 | 手动开始和停止；自动检测会议只做「提醒」，放在最后一个阶段 |
| 上传文件 | 纯 Rust 解码（symphonia，Opus 用 ropus），转成 Ogg Opus 后走和录制相同的会后流程，不打包 ffmpeg |
| 语义搜索 | 不做，只做全文搜索 |
| 设计体系 | Claude 账号里的「xlsama」：黑白灰，克制用色，lucide 图标 |

## 阶段

| 阶段 | 做完能得到什么 | 包含的功能 |
|---|---|---|
| 0. 技术验证（已完成） | 确认路线可行 | 两端音频采集、MAI-2 转写、Rust 说话人识别、纯 Rust 解码 |
| 1. 录制与实时转写（已完成） | 能开一场会并看到实时文字 | 手动开始/停止；来源选择（麦克风、全部系统声音、多选 App）；silero-vad 切句；实时转写；「我 / 对方」双轨；录音和文字存本地；会议列表；设置页 |
| 2. 会后处理与回看（已完成） | 一场会结束后有完整记录 | 整段重跑拿词级时间戳；说话人识别并归到每句话；说话人改名、合并；点文字跳到原音播放；上传音视频；全文搜索；导出 |
| 3. 纪要（已完成） | 会中有大纲，会后有定稿 | 实时话题大纲；每条可点回原句；会后定稿纪要和待办；热词表 |
| 4. 实时白板（已完成） | 会中自动出图，可手改 | Excalidraw 画板；节点可编辑、可点回原句；用户动过的不再改 |
| 5. 认人（已完成） | 跨会议自动认出是谁 | 本地声纹库；「记住声音」；之后的会议自动挂名字；逐句复核提高准确率 |
| 6. 自动化与发布（签名和自动更新未做） | 可以日常使用和分发 | 检测到会议时提醒开录；Windows 适配；打 tag 自动构建两端的安装包并发到 GitHub Release；签名、公证、自动更新 |

线下会议不是单独的阶段：阶段 1 只开麦克风就是线下录制，阶段 2 的说话人识别让它可用。

## 实测数字

- 说话人识别（Kept 的 25 场金标，句级归属）：中文 94.73%，英文 92.38%，和 Kept 现役持平。
- 第一步换成 silero-vad 会掉到中文 93.69%、英文 90.28%，所以保留 pyannote。
- MAI-Transcribe-2 逐句转写：说完到出字多数 0.7–1.5 秒。
- MAI-Transcribe-2 自带的说话人分离：10 分钟音频 93.8%，20 分钟 86.0%，38 分钟的文件 10 分钟内没有返回。这是不用它的原因。
- 解码：23 种格式里 22 种正确；39 分钟 m4a 用 1.7 秒。
- 自定义转写服务（内网自建的 Confucius4-R2T2，只返回文字）：57 分钟、5 个人的会议录音转写 29 秒，其中本地找语音约 7 秒；和 MAI 的定稿比，句子时间的误差中位 0.34 秒、九成在 1.2 秒内，说话人归属 95% 一致（只按停顿切、不在换人处切是 86%）。逐句送的中文会议 CER（Kept 的 AISHELL-4 金标 160 句）12.70%，MAI 是 11.48%。

## 已知问题和没做的

- macOS 的系统回声消除会把系统声音压低约 8 dB，并可能影响其他 App 的麦克风，所以默认只在外放时开（设置里可改成一直开或关）。
- Windows 只在 CI 上验证过，见下面的「Windows」。
- 系统里放着带人声的音乐时，「全部系统声音」会把歌词也当成发言转写，要改成只录指定 App。
- DeepSeek 的语音识别（一次最多 120 秒，只返回文字，0.39 元/小时）：同一场 57 分钟的录音 16 段并发转写 46 秒；句子时间的误差中位 0.32 秒，说话人归属 96% 一致。逐句送的中文会议 CER 17.44%（160 句）和 12.65%（600 句），同样两个集上 Confucius4-R2T2 是 12.70% 和 10.65%，MAI 是 11.48% 和 9.41%；它差在漏字，会把一句的开头或中间整段丢掉。英文和中英混说比 Confucius4-R2T2 好，比 MAI 略差。
- 自定义转写服务不传语言：Confucius4-R2T2 会把一部分英文发言写成中文译文。逐字高亮在句内按字数匀速走，没有词级时间。
- MAI 的会后整段重新转写是一次请求，接口限制单个文件 5 小时以内。MAI 的文档只列了 WAV、MP3、FLAC，实测直接传 Ogg Opus 可用。
- 说话人识别每次调用重新加载模型，超过 40 分钟的会议没测过；Kept 的逐句复核没移植。
- 回放用 Video.js 10（`@videojs/react`，皮肤源码在 `src/components/videojs`）。导入的 MP4 / MOV / WebM 保留原视频（硬链接）并可播放画面，其他视频格式只能播声音；导入的音频能直接播的也用硬链接的原文件回放。录制的会议播 Ogg Opus，macOS 要 15.4 以上。
- 视频画面放在文字稿上方（可收起），这个位置设计稿里还没有。
- MyGo 编译 Rust 模块时会把过程宏库 strip 坏，`Cargo.toml` 里加了 `[profile.release.build-override] strip = false` 绕过。
- 白板的节点和纪要出自同一次模型调用（话题下的短语节点），没有单独的白板请求；白板目前只有话题树一种图。
- 认人只在相似度 0.52 以上时自动挂名字，0.35–0.52 之间的「可能是某人」没有做提示。逐句复核只查存疑的和 4 秒以内的短句，每场最多 400 句。
- 会后的纪要是 ProseKit 文档，可以自由编辑、勾选待办；重新生成会保留上一版，可恢复。录制中的大纲只读。白板仍由模型的原始输出生成，不跟着纪要里的手动修改变。侧边面板里显示的也是模型的原始大纲。
- 会议提醒按「已知的会议 App 或浏览器开始用麦克风」判断，没有在真实会议里试过；浏览器里用麦克风的其他网页也会触发。
- 阶段 6 里没做的：macOS 包在 CI 里的签名和公证（workflow 已支持，要在仓库里配证书和 Apple 账号的 secret）、Windows 代码签名、自动更新。
- MAI-Transcribe-2 是 public preview，$0.10/小时是到 2026-12-31 的促销价。
- 导入不支持 wma，amr 没测。

## Windows

Windows（amd64）和 macOS 用同一份界面和业务代码，没有真机，靠 CI 验证：`.github/workflows/windows.yml`（手动触发）跑两个作业，最后一次通过是提交 `5595c5f`。

- `test`：采集的 Rust 测试、两个原生模块经 Go 的测试、`internal`、`cmd` 和主包的 Go 测试。
- `smoke`：带自动化插件构建应用，用安装程序静默安装，在 runner 的桌面和虚拟声卡上从安装目录实际跑一遍（`cmd/smoke`），最后卸载，每一步截图存在这次运行的产物里：主窗口和设置各页、安装命令行、麦克风加系统声音的一次录制（侧边面板、小条）、会后整理（转写用冒烟脚本里的假服务）、`meetkeep` 的 `status`、`list`、`import --wait`、`wait`、`steps`、`transcript`、两场会议的回放。

和 macOS 不一样的地方：

- 标题栏：系统的最小化、最大化、关闭按钮在右上角，页头给它们让出位置；快捷键写成 Ctrl，侧边面板是 Ctrl+Alt+M。
- 托盘：图标在深色任务栏上用白色；录制的时长写在图标的提示里（任务栏的图标旁边不能放文字）。
- 采集：App 用程序的描述和图标显示；输出是耳机或耳麦时算作戴着耳机；回声消除是把麦克风按通话类别打开，由系统和声卡驱动的回声消除处理，系统支持时把默认扬声器设成参考。
- 回放：WebView2 把 `recording` 协议放在 `http://recording.localhost` 下。
- 命令行：程序是应用目录里的 `meetkeep-cli.exe`（和 `MeetKeep.exe` 不能同名，又要和 `Sqlitecore.dll` 在一起），设置页把 `meetkeep.cmd` 写进 `%LOCALAPPDATA%\Microsoft\WindowsApps`；卸载时删掉它。
- 路径：不把用户目录写成 `~`；设置和数据库仍在 `%USERPROFILE%\.config\meetkeep`。

没验证或没做的：

- 没在真机上用过。回声消除只确认了打开后能录到声音，消没消掉回声要有扬声器和麦克风的真机才知道；通话类别可能让系统压低其他声音。
- 托盘图标点开的弹层、全局快捷键、开机自启、会议提醒和纪要写好的通知：CI 里点不到，没有验证。
- 安装程序只跑过静默安装和卸载，向导界面没看过；没有代码签名，SmartScreen 会提示。
- 自动更新没做。
- 内存占用的记录（`steps` 里的峰值）在 Windows 上是 0。

## 设计稿

画布：https://claude.ai/artifact/1LnD7zSJL8s6p6fBcEBvHR ，只有浅色。

| 分组 | 画板 |
|---|---|
| 会中 · 看着会议 App 时 | 侧边面板（盖在会议 App 上）、面板 · 文字稿 / 纪要 / 白板、收起成小条 |
| App 关着时 | 菜单栏 · 未录制、菜单栏 · 录制中、会后 · 纪要好了 |
| 录制 | 首页、新录制 · sheet、录制中 · 纪要、录制中 · 白板、检测到会议 |
| 会后 | 纪要、白板、整理中、说话人（sheet） |
| 查找与管理 | 搜索、人物、设置 |

布局上的约定：

- 会中的主界面是贴在屏幕右侧的侧边面板：约 400px 宽、与屏幕同高、可拖动宽度，三个 tab（文字稿、纪要、白板），可收起成小条；不带系统标题栏。菜单栏常驻状态项，录制中显示计时。
- 主窗口保留系统标题栏。左侧栏是会议列表，底部是人物和设置；右侧是当前会议，左边文字稿，右边用标签切换纪要和白板。录制控制是文字稿下方的黑色悬浮条。
- 新录制和说话人编辑用 sheet。
- 会中只显示「我 / 对方」，会后才换成真名。拿不准的内容标「存疑」，不变成派给某人的待办。

功能对齐 → 设计稿 → 调整设计稿 → 按阶段实现。现在处在按阶段实现这一步。
